## 확인 못 함

1. 별도 관리자 host(관리 주체 분리) — 두 번째 관리 주체 host가 없어 검증 불가(BLOCKED_BY_ENV, 점수 아님). T5는 같은 호스트의 기능 분리다. ADMIN_BOUNDARY_VALIDATED는 미충족.
2. 호스트 사이 실제 TLS 경로(인증서 검증 포함) — 프로젝트도 평가자도 시험하지 않았다(`SECURITY_MODEL.md:42,107`).
3. 최종 ZIP 스택에서 학습 job 중인 runner 작업 자식 프로세스의 environ — 캡처되지 않았다(근거는 `daemon.py:70-74` 정적 목록뿐; 평가자 실기동 R9에도 job 없음).
4. 실서버 SSE 스트림의 누출 캡처 — 프로젝트 T8 "Not covered"; 인프로세스 SSE replay는 R2가 덮는다.
5. 최종 트리의 canary 심은 시험 빌드(`scripts/package.sh --canary`) — 마지막 실행은 1차 트리(`WP7/7V/canary_build_*`). 평가자는 `build/canary`에 쓰게 되므로 돌리지 않았다(릴리스 ZIP 스캔 R4와 멤버 grep R5로 대신 확인).
6. BENCHMARK envelope — `filter_params`가 BENCHMARK에는 `admission`·`training_outputs`만 빼고 params를 모두 보낸다(`mbnas_core/src/mbnas_core/runner_api/envelope.py:184-192`). 정책 params는 PROPOSE_GENERATION에만 붙고(`orchestration/engine.py:318-321`) 현재 core가 BENCHMARK job을 만드는 경로는 읽은 범위에서 찾지 못했으나 실행으로는 확인 못 함.
7. 평가 도중 트리가 바뀌었다(DD-A64, 머리말 참조). C02 표면 시험은 종료 트리에서 다시 돌렸고(R15·R17) 결과가 같다. R4·R5·R7–R10·R12는 변경 전에 돌렸으나 대상(배포 ZIP·공개 venv·`/proc` 캡처·DB 저장·투영 음성 대조)은 이 변경과 무관하다 — 무관 판단은 diff 열람 근거이며 재실행하지 않았다.
