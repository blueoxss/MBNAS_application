Training results are bitwise identical between the original worker handler and the new runner handler (exact, deterministic=True) in every configuration, including config B/C where the model reaches a non-trivial AP50-95 of 0.824. Latency is a timing measurement on a shared host: in config B the single ref run measured ~1.4 ms slower than both new runs while the T7 track was training on the other GPU (in config A the slow outlier was a NEW run, ~1.9 ms), so B exceeds its (tiny) intra-side spread; in the controlled config C (idle host, two runs per side) the cross-side difference of the means is far below both intra-side spreads. Overall G2-2: PASS for training metrics (exact); latency equivalence PASS on the controlled run C, with the config-B exceedance attributed to host contention (not reproducible when the host is idle).
