# DECISIONS — 설계 결정(DD-A*) 기록 (append-only)

형식: ID · 결정 · 근거 · 영향. 이전 통합 작업의 DD-1~41은 `build/source_snapshot/application/docs/integration_20261021/PLAN_20261021.md`에 있고 의미 보존 대상이다.

- **DD-A1 (2026-10-23) 패키지 분할 원칙.** 원본 `mbnas_server` 단일 패키지를 5개 배포로 분할한다. 분류 규칙: (a) 정책을 *결정*하는 코드(검색 공간 prior/repair/교차/변이/부모 선택, 구조 gate 규칙, fitness·승급·예산·종료, orchestration/DB/RNG 상태) → `mbnas_core`(private). (b) 승인 모델을 *구축·학습·평가*하는 백엔드(adapters, 커스텀 operator, genotype CPU 관측, checkpoint 포맷, 데이터셋 manifest, block catalog 데이터) → `mbnas_model_runtime`(public). (c) 작업 수명주기 실행(worker/child/contract, 학습·평가·벤치 handler, stage_trainer) → `mbnas_runner`(public). (d) DTO·enum·openapi·공유 util(canon/time/atomic/paths/log_redact) → `mbnas_contracts`(public). (e) 사용자 API gateway + 읽기 전용 archive → `mbnas_server`(public). 근거: 지침 §3 보호 대상 2건과 "operator는 고객 장비에서 실행되므로 비밀일 수 없다"는 충돌 해소. 영향: import 경로 재배치, 기존 테스트 재배치.
- **DD-A2 ETRI mixed pool 처리.** `yolo_ga_runtime.mixed_blocks`(NASPatchMerge/NASWindowTransformer/NASGlobalTransformer + parse_model 확장)는 승인 YAML 구축에 필요 → `mbnas_model_runtime.operators`로 vendoring(공개). `mixed_search_space.make_mixed_seed_variants/_legal_choices/mutate_operators/audit_config`는 검색 정책 → `mbnas_core.search.mixed_pool`로 vendoring(private). `yolo_ga_runtime.runtime`은 `REPEAT_MODULES` 집합과 `symbolic_shape_propagate`(mutate_operators 전용)만 참조되므로 필요한 최소 심볼만 이식하고 나머지(crossover_v22, pipeline, mixed_hooks, yolo_ga_full_runtime)는 가져오지 않는다. etri_bridge의 `sys.path` 삽입 import는 제거하고 패키지 import로 대체(원본 체크아웃 참조 금지). 원본 파일 SHA-256은 provenance에 보존.
- **DD-A3 제어면 분리.** core 호스트: `/core/v1/console/*`(gateway용, 공개 DTO 투영 후 응답), `/core/v1/runner/*`(claim→heartbeat→progress→artifact→result→ack), `/core/v1/owner/*`(관리자 scope, 전체 감사 DTO). gateway는 `/api/v1/*` 기존 계약을 유지하여 웹·테스트 호환. 투영은 core 내부에서 수행(고객 측에 private 필드가 도달하지 않음).
- **DD-A4 runner JobKind 허용목록** = {BASELINE_TRAIN, CANDIDATE_TRAIN, FINAL_RETRAIN, EVALUATE, BENCHMARK}. PROPOSE_GENERATION과 structure-check는 owner worker(core 호스트, CPU)에서만. 기존 DB lease(`repo.acquire_lease` UPDATE…RETURNING)를 재사용하고 lease_epoch(=attempt)+runner_id로 fencing.
- **DD-A5 공개 recipe.** 사용자가 작성한 resolved protocol 전체는 고객 입력이므로 envelope에 포함(protocol_hash 검증 의미 보존). private는 core 내부 resolution(prior tables, repair, parent pool, search_state)이며 envelope에 넣지 않는다. runner는 fitness/gate를 계산하지 않고 raw 평가만 보고, core가 source rung 가중치로 재계산(기존 `engine.commit_evaluation` 경로).
- **DD-A6 artifact.** runner가 생성한 artifact는 (runner_id, artifact_id, digest, bytes, kind)로 core에 등록만 하고 바이트는 고객 측 artifact store(기본: 같은 호스트의 `runtime/artifacts`, 다중 호스트는 runner→server 인증 업로드)에 둔다. 다운로드는 server가 digest 대조 후 제공. 재개는 checkpoint affinity(해당 runner_id 우선) + store에서 digest 검증 전송 후 재개.
- **DD-A7 환경/포트.** 앱 Python 3.10(mbnas310 인터프리터로 venv 생성, system-site-packages=false), cu124 wheelhouse 1회 다운로드 후 모든 클린 설치는 `--no-index --find-links`. 포트 8700/8710/8720, DB/출력은 `runtime/` 하위. GPU 검증은 사용자 승인 창에서만.
- **DD-A8 웹 private 제거.** `src/lib/fitness.ts computeFitness`(CandidateView 1곳 사용)와 `policy.ts`의 handoff 원문 embed는 public 번들에서 제거/대체: fitness는 서버 계산값만 표시, 템플릿은 `GET /protocols/presets` 응답 사용. 사용자 편집 protocol JSON 자체는 사용자 입력이므로 유지.
- **DD-A9 라이선스 검토 보류 항목.** ultralytics 8.4.173은 AGPL-3.0 → 배포·결합 의무 검토 필요(REST/발췌로 소멸 주장 금지). rfdetr Apache-2.0, torch BSD-3. etri_nas 루트에 LICENSE 없음 → ETRI/권리자 확인 필요. 논문(main.tex 407행 각주): "publicly released upon publication" 공개 약속 존재(서버에 원문 있음, 직접 확인). 이 보류가 구현·시험을 막지 않는다.
